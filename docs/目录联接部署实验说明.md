# v3.8.4 目录联接部署实验说明

本实验版本从未修改的 v3.8.0 基线开发。它保留原有复制模式，并允许每个仓库单独启用 Windows 目录联接部署。

## 工作方式

启用“使用目录联接部署 Mod（实验）”后，管理器不会把第二层 Mod 完整复制到加载器目录，而是在目标 Mods 文件夹创建一个目录联接：

```text
加载器 Mods\ModA  ->  仓库\分类\ModA
```

加载器访问联接时看到的仍是普通文件夹。通过联接读取或写入的文件就是仓库里的实际文件，因此 Mod 自己在其文件夹内生成或重写的 INI、JSON、CFG 等文件会直接保留在仓库中。

普通 Windows `.lnk` 快捷方式不参与此功能。实验版本创建的是 NTFS reparse point（directory junction）。

## 安全规则

- 只允许链接选定仓库内部的 Mod。
- 不覆盖已经存在的目标文件或文件夹。
- 移除联接时要求目标具有 `ReparsePoint` 属性，只删除联接入口。
- 普通目录继续使用原版的安全递归删除逻辑。
- 安装事务把联接目标记录到清单，撤销时重新创建联接。
- 如果备份清单中的联接目标不在对应仓库中，拒绝恢复。
- 不允许联接路径与目标路径互相包含，避免目录循环。

## 使用步骤

1. 选择或创建仓库，并设置 Mod 仓库路径与加载器 Mods 目标路径。
2. 打开“使用目录联接部署 Mod（实验）”。该设置按仓库保存。
3. 双击第二层 Mod，或使用“部署当前第二层文件夹”。
4. 状态显示“已链接”即创建成功。
5. 再次操作会移除链接入口，仓库原 Mod 保持不变。
6. 配置方案应用同样遵循当前仓库的复制或链接模式。

## 同角色自动切换

在链接模式下，同一第一层角色文件夹只保留一个通过单项部署建立的活动目录联接。例如：

```text
仓库\庄方怡\Mod A  ->  加载器 Mods\Mod A（当前已链接）
仓库\庄方怡\Mod B  ->  用户准备链接
```

部署 `Mod B` 时，管理器会先把 `Mod A` 和 `Mod B` 一起写入安装事务，断开 `Mod A` 的联接，再建立 `Mod B` 的联接。任何一步失败都会尝试恢复原来的 `Mod A` 联接。

- 只会自动断开同一第一层角色目录下的旧联接。
- 只会处理解析目标与仓库兄弟 Mod 完全一致的目录联接。
- 不删除仓库 Mod，不删除普通复制目录，不影响其他角色的联接。
- 配置方案仍以方案中明确选择的 Mod 集合为准，因此可以表达多 Mod 组合。

## RAR 解压兼容性

新版 7-Zip 会在普通 RAR 文件条目中输出空的 `Symbolic Link =`、`Hard Link =` 和 `Copy Link =` 属性。v3.8.4 只在这些属性包含实际链接目标时拒绝解压；空属性不再误报。目录穿越和真实链接仍会在正式解压前被阻止。

## 与 XXMI 持久变量的区别

目录联接只覆盖目标 Mod 文件夹内的文件。XXMI 的 `global persist` 变量通常写到 EFMI 根目录的 `d3dx_user.ini`，不属于 Mod 文件夹，因此不会因为建立目录联接而自动写入仓库。

本实验版可验证“浅拷贝”和 Mod 本地文件回写，但不能把它等同于跨卸载保留所有 `$变量`。如果 XXMI 在 Mod 卸载后清理 `d3dx_user.ini` 中的 namespace，仍需常驻门控或状态槽方案。
