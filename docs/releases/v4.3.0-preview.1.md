# 4.3.0-preview.1：内置终末地启动、INI 冲突检测与 Mod 库修复

这是 4.3 的第一个开发预览版，按 GitHub 预发布通道提供，v4.2.0 稳定通道继续保留。本预览版关闭软件自身的自动更新，Mod 下载和更新功能不受影响。

This is the first 4.3 development preview, published as a GitHub prerelease. The v4.2.0 stable channel stays in place, and application self-update is off in this preview.

## 主要变化

1. **内置终末地启动**：EndfieldBridge 0.3.2 的启动核心已并入管理器，不再需要单独下载桥接器，也不再经过 cmd 和桥接窗口；“运行启动器”只弹一次 UAC。入口在仪表板 → 当前仓库路径 → 启动方式。原生设置页可以检测配置、读取 / 备份并适配 / 恢复 EFMI，并查看启动日志。打开设置页或运行启动器时，会自动读取旧桥接器的设置并接管其 EFMI 恢复点。说明见 [内置终末地启动](../guides/zh-CN/终末地启动.md)。
2. **EFMI 恢复更安全**：保存设置时会写入 XXMI 回调要读的配置；另一套 XXMI 的恢复点不会被覆盖，原 XXMI 已删除时，旧恢复点会存档作废；恢复前核对适配时写入的字段，用户后来改过的不会被冲掉；XXMI 配置旁的备份只保留首次那份和最近 5 份。
3. **INI 冲突检测**：安装前除了比较文件，还会检查与已启用 Mod 共用的 `TextureOverride` / `ShaderOverride` 哈希和快捷键；跳过 `DISABLED`，尊重 `match_priority` / `allow_duplicate_hash`。只做提示，不阻止部署。
4. **失效联接（#10）**：删除 Mod 时会一并移除加载目录中指向它的联接（只删联接本身）。源目录被删除、改名或移动后残留的联接，不再导致安装时提示“无法检查所选 Mod 的目录或链接”；部署前会列出这些联接，并可一键清理。
5. **压缩包导入（#11）**：每个压缩包只安装为一个 Mod 文件夹。根目录直接放文件的，会自动建立文件夹；已有单个顶层文件夹的，不再多套一层；同名文件夹不合并、不覆盖。修复了“导入压缩包”按钮把文件直接解压进角色目录，以及仓库不在系统盘时拖放导入失败的问题。
6. **稳定性**：同一安装目录只运行一个实例，再次启动会前置已有窗口；异步界面操作的意外异常会被记录并提示，不再直接退出；`app-errors.log` 达到 1 MB 时自动轮转。

## 使用与升级

完整解压 ZIP 后，运行根目录的 `IntegratedModManager.exe`。建议保留旧程序和配置备份，并放在较短、可写的路径下。需要迁移时，先退出新旧两个程序，再复制自己的 `WinUI3/config.ini` 和 `WinUI3/beta-shell.json`；首次打开时请重新核对仓库、目标目录和启动器路径。

用过旧版 EndfieldBridge 的用户：如果之前通过它适配过 EFMI，请在新设置页点一次“备份并适配 EFMI”，把命令改为指向管理器，原始恢复点会保留；随后在 XXMI 中再选择一次“保持”。

## 已知问题与未验证范围

- 尚未用真实游戏和 XXMI / EFMI 走过完整启动链，也未验证 UAC 行为。内置启动和第三方 Mod 注入可能导致账号处罚，测试通过不代表官方认可或账号安全。
- 失效联接清理和压缩包导入的界面流程，只做了构建和逻辑测试，未在真实 Mod 库上实机点击验证。
- 原 `Microsoft.UI.Xaml.dll / 0xc000027b` 原生闪退的根因仍未确认；旧更新器在临时目录过深时仍可能触发 Windows 路径长度限制。
