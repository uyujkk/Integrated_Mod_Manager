# v4.8.5

基于 v4.8.4 的 Windows x64 正式版。Windows x64 stable release based on v4.8.4.

## 更新内容

这是一个修复版本。用户反馈用目录联接部署的 Mod 无法关闭（[#154](https://github.com/uyujkk/Integrated_Mod_Manager/issues/154)），本版本修复了这个问题，并修复了检查时发现的一个相关问题（[#155](https://github.com/uyujkk/Integrated_Mod_Manager/pull/155)）。

- **联接部署的 Mod 可以正常关闭**：
  - 开启“使用目录联接部署 Mod”后，双击已部署的 Mod 或点“从目标文件夹移除”，以前总会提示“Mod 仓库和加载器的 Mods 文件夹重叠”，什么都不改。原因是 4.8.0 加入的重叠检查把管理器自己建的联接也解析了一遍，结果总是指回 Mod 自己的文件夹。
  - 现在检查只解析部署文件夹上面的各级目录，不解析部署文件夹本身。加载器的 Mods 文件夹设在仓库里面，或通过链接指进仓库时，仍然会在改动任何文件之前停止。
  - 移除时只删除联接本身，仓库里的 Mod 不受影响。
  - 加载器里同名的链接如果指向别处（另一个 Mod 或你自己建的链接），会先显示它指向哪里并询问。即使确认，也只删除链接，不会改动它指向的文件夹。
- **仓库路径本身经过联接或符号链接时，管理器认得出自己的链接**：
  - 以前仓库文件夹如果是一个链接（例如 `G:\Mods` 指向别的磁盘），部署链接里记的路径和 Windows 解析出的真实路径不一致。结果关闭 Mod 时备份会把它当成“指向仓库外的联接”而拒绝；同角色切换 Mod 时找不到旧链接，导致一个角色同时链着两个 Mod；组合预设认不出已经启用的 Mod。
  - 现在这些检查同时按记录的路径和解析后的真实路径比较。指向仓库外的链接仍然会被拒绝。
- **其他**：
  - Windows App SDK 更新到 1.7 的服务更新 1.7.260224002，Windows SDK 构建工具更新到 10.0.26100.9457（[#153](https://github.com/uyujkk/Integrated_Mod_Manager/pull/153)）。运行库随程序一起打包，不需要另外安装。
  - 新的确认文字有中文、英文和俄文。主程序、启动器、更新器和开发者工具使用 4.8.5。“新功能”对话框更新为 4.8.5 的内容，升级后显示一次。

## 已知问题

- 联接部署的修复由使用真实目录联接的自动测试覆盖，但还没有在真实游戏和 EFMI 加载器里核对。
- 新的“外部链接”确认框没有截图检查，俄语文字没有请母语者审校。
- 角色重命名时，仍只按链接里记录的路径查找联接。只有用另一种写法的仓库路径建的链接才会漏掉，管理器自己不会建出这样的链接。
- 4.8.4 列出的已知问题仍然有效：在线页没有在高对比度主题和俄语下截图检查，以及 4.8.3 列出的真实游戏和真实账号核对项。见 [v4.8.4 发布说明](v4.8.4.md#已知问题)。
- 真实游戏与加载器的其他验证范围见 [v4.8.0 发布说明](v4.8.0.md#尚未在真实游戏中核对的功能)。

## What's new

A fix release. Users reported that Mods deployed with directory junctions could not be turned off ([#154](https://github.com/uyujkk/Integrated_Mod_Manager/issues/154)). This release fixes that and a related problem found while checking it ([#155](https://github.com/uyujkk/Integrated_Mod_Manager/pull/155)).

- **Junction-deployed Mods can be turned off again**:
  - With **Deploy Mods with directory junctions** on, double-clicking a deployed Mod or choosing **Remove from target** always stopped with "The Mod repository and the loader's Mods folder overlap" and changed nothing. The overlap check added in 4.8.0 followed the manager's own junction, which always led back to the Mod's own folder.
  - The check now follows every folder above the deployed folder, but not the deployed folder itself. A loader Mods folder inside the repository, or one that reaches it through a link, still stops before any file is changed.
  - Removing it deletes only the junction; the Mod in the repository is not touched.
  - A same-named link in the loader folder that points somewhere else (another Mod, or a link you made) now shows where it points and asks first. Even then only the link is removed, never the folder it points to.
- **The manager recognises its own links when the repository path goes through a junction or symbolic link**:
  - When the repository folder was itself a link (for example `G:\Mods` pointing to another drive), deployment links stored one path while Windows resolved them to the real one. Turning a Mod off was then refused by the backup as "a junction pointing outside the repository", switching Mods for the same character missed the old link and left two Mods linked for one character, and combination presets did not recognise enabled Mods.
  - These checks now compare both the stored path and the resolved real path. Links pointing outside the repository are still refused.
- **Other**:
  - The Windows App SDK moves to the 1.7 servicing update 1.7.260224002, and the Windows SDK build tools to 10.0.26100.9457 ([#153](https://github.com/uyujkk/Integrated_Mod_Manager/pull/153)). The runtime ships inside the app, so nothing extra needs installing.
  - The new confirmation text is in Chinese, English and Russian. The app, launcher, updater and Developer Tools use version 4.8.5. The What's New dialog describes 4.8.5 and shows once after upgrading.

## Known issues

- The junction fixes are covered by automated tests with real directory junctions, but have not yet been checked in a real game with the EFMI loader.
- The new "Link from elsewhere" confirmation was not checked with screenshots, and its Russian text has not been reviewed by a native speaker.
- Renaming a character still finds junctions only by the path stored in them. It misses only links made with a different spelling of the repository path, which the manager itself does not create.
- The known issues listed for 4.8.4 still apply: the Online page was not checked with screenshots in a high-contrast theme or in Russian, and the real-game and real-account checks listed for 4.8.3 remain open. See the [v4.8.4 notes](v4.8.4.md#known-issues).
- See the [v4.8.0 notes](v4.8.0.md#not-yet-confirmed-in-a-real-game) for the scope of other game and loader verification.
