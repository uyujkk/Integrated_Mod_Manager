# 4.2.0-preview.2：P0 / P1 优先处理

此版本在 preview.1 基础上补充恢复能力与闪退诊断，原版本目录和整合包保留。它仍是开发预览版，软件自身自动更新关闭，Mod 在线功能保留。

## 本次修改

- 下载任务在本地 `WinUI3/backups/download-queue/tasks.json` 持久化，保留原仓库、目录和选定文件。重启后，运行中的任务标为“中断”，不会自动执行；在更新页手动重试时先展示原位置并确认，从头重新下载。已经完成、失败和取消的历史保留。
- 记录先写完整临时文件并刷新，再原子替换；保留前一份备份。主记录损坏时尝试备份并提示，原损坏内容另存；两份均不可读时保留文件并阻止创建新的下载任务，避免空记录覆盖证据。
- 旧库导入采用版本 2 记录：复制前保存意图，暂存目录携带唯一所有权标记，发布后登记完成。中断恢复仅补登记所有权和内容均可确认的完整副本，修改或无法确认的目录保留；暂存目录不会自动删除。兼容版本 1 的撤销记录。
- 启动时检查中断导入；仓库页“整理导入 → 检查中断的整理导入”可以选择本仓库的记录，补登记后可按现有规则撤销未修改副本。每次最多检查最近 100 份导入记录。
- 搜索匹配行明确说明仅搜索当前页；作者分页状态说明文字仍只过滤当前页。`author:名字` 不是全站作者搜索。
- 详情窗格的延迟动画和下载状态回调增加窗口关闭及版本检查，避免关闭后继续更新失效界面对象。这是对异步生命周期风险的加固，尚未证明它是原始闪退的原因。
- 默认在 `WinUI3/diagnostics/ui-action-context.json` 保存最近 32 个关键操作的本地上下文，包括版本、时间、条目 ID、窗口尺寸和正常关闭标记；下一次启动保留上一次记录。没有路径、URL、凭据或 Mod 描述，不上传。诊断报告包含当前与上次记录；完整布局追踪仍需显式启用。
- 开发捕获脚本增加独立监测期限看护；到时使用 ProcDump 官方取消命令退出监测并保留应用运行，不再把单次转储超时误作监测总时长。

## 仍需注意

- 原始 `Microsoft.UI.Xaml.dll / 0xc000027b` 闪退缺少 stowed 回溯，根因尚未确认，不能宣称已修复。
- 下载任务恢复不等于断点续传。中断留下的压缩包和解压副本保留；重试前应检查原位置，已提交的安装仍会经过重复安装提示。
- 导入恢复不自动继续复制或删除暂存目录，不提供任意断电场景的事务保证，也不能阻止其他程序同时修改文件。
- 旧库整理仍为每批一个目标角色，收藏上限仍为各 100；这些 P2 扩展本次未增加。
- 原地升级和配置回退只在 G 盘隔离副本验收；真实用户库、游戏运行和远端 CI 状态以本轮验收记录为准。本地包不代表正式发布。

使用方式见根目录“开始使用.md”；精确测试、包校验和升级结果见随包验证状态及交付验收记录。
