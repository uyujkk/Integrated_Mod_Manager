## 中文

### 4.3.0 发现的问题与处理

- 已复现：在“更新”模块切换 Mod 检查频率时，程序可能在保存设置后崩溃，所以重启后频率已经改变。隔离复现日志记录了 `COMException 0x8000FFFF`。
- 原因是选择事件中刷新整页，清空并重建了正在处理选择的下拉框。4.3.1 去掉该回调内的整页刷新，并复用频率选项；软件更新频率也采用相同修复。
- **4.3.0 已撤出正式自动更新通道，请升级到 4.3.1。** 旧附件已加 WITHDRAWN- 前缀，阻断缓存中的标准下载地址；已安装程序和已经下载到本机的旧包无法远程撤回，请勿继续安装 4.3.0。

### 4.3.1 新增与修复

- 手动或按频率启动检查发现 Mod 更新时，显示应用内弹窗，可选择“查看更新”或“稍后”。
- 更新卡新增“下载并替换”：选择具体文件／变体，确认原路径，再下载、解压并替换本地 Mod 文件夹。
- 替换前检查原目录内容是否变化，旧文件和原跟踪记录保存在仓库旁的 `.imm-mod-update-backups`；原路径不变，不合并新旧文件。下载、解压可取消，目录交换阶段不再取消。
- 中断替换任务重启后需要重新检查和确认，不会作为普通下载自动重放；检查失败也不会误报为“已经是最新”。

### 包含的 4.3 更新

- **内置终末地启动**：不再需要单独下载 EndfieldBridge 或打开桥接窗口；原生设置页支持路径检测、启动日志、EFMI 备份／适配／恢复，并迁移旧桥接器设置与恢复点。
- **EFMI 恢复保护**：保存时同步 XXMI 回调配置，保留原始恢复点，防止另一套 XXMI 覆盖；恢复前核对适配字段，保护后续修改。
- **INI 冲突提示**：安装前检查与已启用 Mod 共用的资源哈希和快捷键，由用户选择取消或继续。
- **失效联接修复（#10）**：删除 Mod 时清理关联联接，部署前可清理失效联接，避免残留联接导致所有安装检查失败。
- **压缩包导入修复（#11）**：每个压缩包导入为一个 Mod 文件夹，兼容根目录散文件和单顶层文件夹，不静默合并或覆盖已有目录；修复直接解压到角色目录、在线下载多套目录和跨盘拖放导入问题。
- **稳定性与软件更新**：同目录单实例，异步界面异常记录与提示，错误日志轮转；正式版软件更新检查遵循已保存的启动检查和手动检查偏好。

### 升级与使用

- 更新前退出程序并备份配置。完整解压 ZIP 到较短的可写目录，运行 `IntegratedModManager.exe`。手动迁移时，在新旧程序均退出后复制 `WinUI3/config.ini` 和 `WinUI3/beta-shell.json`；保留旧程序和配置用于回退。
- 4.3.0 用户建议立即升级；4.3.0-preview.1 与 4.3.1-test.1 关闭了软件自身更新，需要手动下载正式包。
- Mod“下载并替换”是**整个文件夹替换，请选择完整版本包**。补丁包按作者说明手动安装。旧版备份不会自动清理；目录联接保持原路径，复制部署到加载器的副本需重新部署。
- 旧 EndfieldBridge 用户如曾适配 EFMI，请在新设置页点一次“备份并适配 EFMI”，随后在 XXMI 中再选择一次“保持”；原始恢复点保留。

## English

### Issue discovered in 4.3.0 and its withdrawal

- Reproduced: changing the Mod update-check interval in Updates can crash the app after saving the setting. The new interval therefore takes effect after restarting. The isolated reproduction recorded `COMException 0x8000FFFF`.
- The selection handler refreshed the whole page and recreated the ComboBox while it was processing a selection. Version 4.3.1 removes that refresh and retains the option objects. The app-update interval uses the same fix.
- **4.3.0 has been withdrawn from the stable automatic-update channel. Upgrade to 4.3.1.** Old assets now carry a WITHDRAWN- prefix to invalidate cached standard download URLs. Installed programs and packages already downloaded locally cannot be recalled remotely. Do not install 4.3.0.

### New and fixed in 4.3.1

- Show an in-app notification when manual or scheduled startup checks find Mod updates, with View updates and Later choices.
- Add Download and replace to update cards. Choose a specific file or variant, confirm the original path, then download, extract and replace the local Mod folder.
- Check for changes to the original folder before replacement. Retain the old files and tracking record in `.imm-mod-update-backups` beside the repository. Keep the original path and do not merge old and new files. Downloading and extraction can be canceled; the directory swap cannot.
- Require a fresh check and confirmation after an interrupted replacement; never replay it as an ordinary download. Failed checks no longer report that a Mod is up to date.

### Included 4.3 changes

- **Integrated Endfield launch:** no separate EndfieldBridge download or bridge window. Native settings provide path checks, launch logs, EFMI backup / setup / restore, and migration of old bridge settings and restore points.
- **EFMI restore protection:** save XXMI callback configuration, retain original restore points, prevent another XXMI installation from overwriting them, and check adapted fields before restoring to protect later edits.
- **INI conflict warnings:** compare resource hashes and shortcuts with enabled Mods before installation, allowing the user to cancel or continue.
- **Broken-link fixes (#10):** remove associated links when deleting a Mod and offer broken-link cleanup before deployment, preventing stale links from failing every installation check.
- **Archive-import fixes (#11):** import each archive as one Mod folder, handle loose root files and single top-level folders, and prevent silent merging or overwriting. Fix direct extraction into character folders, extra nesting in online downloads and cross-drive drag-and-drop imports.
- **Stability and app updates:** one instance per installation directory, exception reporting for asynchronous UI actions, error-log rotation, and stable app-update checks that honor saved startup-check and manual-check preferences.

### Upgrade and use

- Exit the app and back up configuration before updating. Extract the complete ZIP into a short, writable folder and run `IntegratedModManager.exe`. For manual migration, copy `WinUI3/config.ini` and `WinUI3/beta-shell.json` after both versions have exited. Keep the old program and configuration for rollback.
- Users of 4.3.0 should upgrade immediately. Version 4.3.0-preview.1 and 4.3.1-test.1 disable app self-updates and require a manual download of this stable package.
- Mod Download and replace performs a **complete folder replacement; select a complete version package**. Install patches manually following the author's instructions. Backups are not automatically deleted. Directory links keep the same path; copies deployed to the loader must be deployed again.
- If the old EndfieldBridge adapted EFMI, use Back up and set up EFMI once in the new settings page, then select Keep again in XXMI. The original restore point is retained.
