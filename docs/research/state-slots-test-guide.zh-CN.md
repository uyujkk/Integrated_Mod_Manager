# 4.0-beta：先恢复 Mod 组合，再恢复加载器参数

这是基于 v3.9.5 原型整理的独立 Beta，不是稳定版更新包。请将整个包放在新的可写目录，不要覆盖正式应用目录。软件更新检查、下载和安装已强制禁用，即使旧配置开启也不会生效；在线 Mod 更新不受影响。当前环境的组合与状态恢复已由用户实际测试确认，其他 Mod、游戏和加载器仍需验证。

## 1. 启动与入口

完整解压，双击根目录 `IntegratedModManager-Beta.exe`。不要只拷贝 EXE；它依赖旁边的 WinUI3 文件夹。

环境要求：Windows x64、.NET 8 x64 运行时（Microsoft.NETCore.App）；Windows App SDK 运行文件已包含。本机已检测到 .NET 8 x64。若其他电脑报缺少 .NET，应安装 Microsoft 官方 .NET 8 x64 Runtime。

首次启动自动建立“状态槽位离线测试 / Offline Demo”仓库。进入“仓库”，左侧选 TestCharacter，中间选 TestModA，在右侧打开“状态槽位”标签。窗口顶部应有 `v4.0-beta` 标识。

继续保留原型的边界：Mod INI 只读取，不再改写。组合功能可以更改加载器 Mods 文件夹的复制/联接部署，但持久参数只写入选择的 d3dx_user.ini。若迁移 R2/R3 测试版，关闭两版应用后，可将旧测试包 WinUI3 下的 config.ini 和 beta-shell.json 复制到新测试包对应目录。先备份配置，不要覆盖正式应用。

选择保存的槽位后，下方会显示捕获到的 INI 文件、变量名和数值，便于核对 A/B 两组状态。

配置、槽位和缓存只写在测试包的 WinUI3 文件夹里。保存槽位位置：`WinUI3/beta-shell.json` 的 `ModPersistentSlots`；组合位置为 `ConfigurationProfiles`，每个组合记录 `ModRelativePaths`、`IncludesPersistentState` 和 `PersistentStates`。旧的仅组合方案继续兼容，不自动补造参数。

## 1.1 新增：保存并一键恢复多 Mod 组合

入口在“更新”页的“Mod 组合预设（实验）”。状态槽位页也有直达按钮。

1. 在游戏中把当前启用的各 Mod 调整到想要的状态，按 F10 并等待加载器文件保存完成。
2. 在更新页选择正确的 d3dx_user.ini，勾选“新建/更新时同时保存 d3dx_user.ini 参数”，点击“新建方案”，命名，例如“组合 A”。应用记录当前仓库里已部署的 Mod 与每个 Mod 的数值型持久变量。
3. 游戏中换另一套 Mod 组合/外观，保存文件后，新建“组合 B”。参数是按完整 namespace 保存的，不是把两个 Mod 的同名 `$x` 混在一起。
4. 完全退出游戏和 XXMI/EFMI，选择“组合 A”，点击“恢复组合”。预览安装/移除清单、参数文件与修改数量，勾选已退出，确认后执行。
5. 应用先备份部署目录并恢复组合，核对启用列表，再一次性定向回写所有已保存参数并重新读取核对。其他 Mod 的参数、注释和其他段落保留；没有整份覆盖共享配置。即使启用组合已经一致，也会恢复参数。
6. 重新启动加载器与游戏验证实际外观。要测试“组合 B”，再次完全退出后恢复 B。

只想保存启用列表，可以取消勾选参数选项。它影响新建/更新，不会临时改变已有预设的恢复内容；更新会覆盖选中的预设，执行前需确认。

参数捕获遇到已声明但没有对应运行值的变量时会拒绝保存，不用 Mod 默认值冒充当前状态。无数值型持久声明的 Mod 仍可加入组合，其参数数量为 0。旧 Mod 残留在 d3dx_user.ini 的参数不会使它自动成为组合成员；组合成员来自实际部署目录。仍须亲自确认当前 Mod 已实际加载且已保存最新状态。

当前只管理所选仓库中能识别的两层“角色/Mod”目录；其他仓库、未知目标文件夹和外部联接不自动移除。普通复制按唯一同名目录识别，不能据此区分一个手动创建的同名副本；恢复前务必核对预览中的移除清单。目录联接会核对实际目标。缺失/禁用 Mod、重复同名部署、命名空间冲突、无效参数、文件在确认期间变化都会停止，而不是悄悄跳过。

离线测试：首次示例中 TestModA 与 TestModB 均已复制部署，在更新页保存“组合 A”（2 个 Mod，3 个持久参数）；选择 StateB 的文件保存“组合 B”，然后选回 Loader/d3dx_user.ini，退出加载器确认后恢复 B。预期 A 的 hair=2、coat=1，B 的 style=3；temporary 与 Unrelated 的值不变。恢复 A 则返回 hair=1、coat=0、style=2。还可移除一个示例 Mod，保存仅启用另一个的组合，再测试恢复清单。

部署失败或参数写入失败时尝试恢复本次部署备份；若参数已写入而后续步骤失败，只在文件仍等于本次写入结果时回滚参数，不覆盖随后发生的其他编辑。部署“撤销”按钮只撤销部署，不撤销持久参数；参数恢复使用旁边的 `.imm-persist-*.bak`，有后续配置变化时应先比对，不能盲目全覆盖。

## 1.2 Alt+Tab 与选择稳定性检查

R3 移除了“把 Mod 游戏快捷键当成管理器跳转/部署命令”的执行路径。快捷键模块仍可显示、识别和编辑，只作为游戏按键说明。Tab/Alt+Tab、Alt+Esc、Alt+F4 和 Windows 组合键不会被按键编辑器记入或覆盖原记录。仓库列表取消“焦点跟随选择”，刷新后尽量保留当前选择，过期异步刷新结果不覆盖新的仓库。

验证：先选一个非首项 Mod，Alt+Tab 到其他窗口并切回，确认当前角色、Mod、状态槽位和部署目录均未改变；在快捷键编辑框中重复，确认记录未被 Alt+Tab 覆盖。此项仍需在可见的用户桌面测试，编译和进程启动不等于验证真实窗口切换。

## 2. 不启动游戏的快速测试（建议先完成）

示例文件都是模拟数据，没有游戏资源，不能当真实 Mod 安装到游戏加载器。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 选 TestModA，保持默认的 Loader/d3dx_user.ini，点“保存新槽位”，命名 A | 下拉列表出现 A，捕获 2 个变量，不含 temporary 或其他 Mod 的变量 |
| 2 | 点“选择文件”，选择包内 TestData/StateB/d3dx_user.ini，保存槽位 B | B 也是 2 个变量；A、B 同时存在 |
| 3 | 把文件改回 TestData/Loader/d3dx_user.ini，选 B，点“恢复到加载器”，勾选已退出游戏和加载器，再“备份并恢复” | 工作文件中 TestModA 的 hair=2、coat=1；其他 Mod、temporary 和所有 Mod INI 不变；工作文件旁生成 .bak |
| 4 | 改选 A，再恢复到加载器 | 工作文件中 TestModA 的 hair=1、coat=0；A 与 B 可重复切换 |
| 5 | 选 TestModB，保存一个槽位，随后切回 TestModA | B 只捕获 style；TestModA 的 A、B 不串到 TestModB |
| 6 | 正常关闭测试应用，再次启动，重新选择 TestModA | A、B 仍在，可以再次恢复 |
| 7 | 再恢复已一致的槽位，并比较工作文件与 Mod INI | 显示“已一致”，不重复写入或创建新备份；Mod INI 始终保持原样 |
| 8 | 删除一个槽位 | 仅删除槽位记录，Mod INI 和备份不被删除 |

StateA 和 StateB 是参考样例。恢复按钮写入的是路径框当前选择的文件，测试时请选 Loader/d3dx_user.ini 作为工作文件，不要误将参考文件作为恢复目标。

上述测试通过，只说明快照、精确运行键恢复、隔离、备份和配置保存可用，不证明游戏内的外观已经恢复。

## 3. 真实 XXMI/EFMI 测试

1. 复制一个不重要、确实包含 `[Constants]` 中数值型 `global persist` 的 Mod 到 G 盘测试仓库。备份整个测试 Mod 和真实加载器的 d3dx_user.ini。不要用正式仓库做首次测试。
2. 在测试应用中新建独立仓库，配置测试源目录和要测试的加载器 Mods 目录。两个目录必须不同，目标不要指向源目录。普通复制或目录联接都可以，但每次只测试一种部署方式。
3. 部署 Mod A，启动游戏，确认实际加载的是这一份 Mod。调出一套易辨认的发型/服装状态，在游戏中按 F10，检查加载器 d3dx_user.ini 的修改时间确实更新。
4. 回到测试应用，选中 Mod A，在“状态槽位”中选择这次加载器的真实 d3dx_user.ini，保存为“外观 A”。不要使用包内模拟文件。
5. 回游戏调整另一套明显不同的外观，再按 F10；回应用捕获“外观 B”。确认两次保存均匹配到有效变量。
6. 完全退出游戏和 XXMI/EFMI。可先部署另一 Mod B，再切回 A，确认 A 已以保存时的同名目录部署。选择“外观 A”，点“恢复到加载器”，核对目标路径及修改/补入/已一致数量，确认后执行。
7. 检查 d3dx_user.ini 对应的完整运行键、自动备份与写入后的核对结果。Mod INI 不应发生变化。不必因为恢复槽位而重新部署 Mod；只需确认当前部署的是要恢复的 Mod。重新启动加载器与游戏，观察是否呈现“外观 A”。
8. 完全退出，再恢复“外观 B”，按相同步骤重启，观察是否呈现“外观 B”。单独重复一次“切换其他 Mod 后再切回”的过程。

### 如果运行键核对成功，游戏仍是旧外观

这应记录为“文件恢复成功，游戏恢复失败”，不要记成成功。先确认恢复后才启动游戏/加载器、选对了活动 d3dx_user.ini 和部署目录；再对比重新启动后相关运行键是否被重写，检查 Mod 初始化脚本是否覆盖状态。

R2 只更新经过当前 Mod 声明验证的完整运行键；已不存在的键补入唯一的 [Constants] 段，重复键、无效值、声明/namespace 失配时拒绝恢复。没有整份槽位覆盖共享配置，不删除其他键，不模拟 F10，不读取游戏内存，不向游戏注入。应用不强行结束游戏进程；退出状态需要你亲自确认。

## 4. 回退与结果记录

关闭游戏和加载器，在 d3dx_user.ini 旁找到对应的 `d3dx_user.ini.imm-persist-*.bak`。每份备份保存该次写入前的整个原始文件；选择该次恢复生成的正确备份。在没有后续其他配置改动时，可以将其复制回 d3dx_user.ini。若期间其他 Mod 也更新过配置，不要直接用旧备份覆盖，应先核对差异。不要误用不同时间的备份。

退出测试应用后，可直接放弃这一整个测试目录；正式应用不会被升级。需要保留槽位时，备份 WinUI3/beta-shell.json 及测试源 Mod。目录移动、Mod 重命名、INI/namespace 改变可能使已有槽位失配，需要重新捕获。

反馈时记录：游戏/加载器版本、Mod 名称、复制或联接部署、捕获变量数、对应 INI 的 global persist 声明与该 Mod 的运行键、写入前后数值、重启后的外观、是否覆盖已有 d3dx 值。可以附脱敏截图与该 Mod 的相关几行配置；不必上传整份 d3dx_user.ini 或私人路径。

## 5. 支持边界

当前支持数值型 global persist、默认 namespace 或明确 namespace、UTF-8 / BOM UTF-8 / BOM UTF-16。非持久临时变量、字符串、表达式、复杂脚本不保存；禁用 INI 和重解析点不扫描。INIs 有大小和数量上限。

不等于跨任意 Mod 转移同一套服装参数；槽位按仓库和 Mod 路径隔离。本版是“保存多个 Mod 的启用组合和各自状态，切回来恢复”的 Beta。用户已确认当前环境恢复成功，但尚不能据此宣称所有 Mod 兼容，暂不作为稳定版发布。
