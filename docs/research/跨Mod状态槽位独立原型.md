# 跨 Mod 状态槽位：独立原型（未发布）

本原型从 v3.9.5 主线建立在 G 盘的独立分支 `experiment/cross-mod-presets`。正式 v3.9.5 目录及 GitHub 发布包未修改。本功能不是对任意 XXMI Mod 的通用状态恢复承诺。

R2 根据实际文件反馈调整：初版写 Mod 默认值未能改变 d3dx_user.ini 中的活动值。现已弃用 Mod INI 写回，只保留读取声明和 namespace；恢复时备份后定向更新 d3dx_user.ini。R3 进一步支持多 Mod 启用组合与参数快照，以下单 Mod 流程继续保留。

## R3：共享加载器文件与组合快照

实际反馈确认 `d3dx_user.ini` 同时保存多个 Mod 的运行参数，甚至可能含已不再启用 Mod 的旧键。因此组合成员从加载器 Mods 目录识别，不从共享文件里出现了哪些键推导。新组合预设同时记录启用列表与每个 Mod 的完整 namespace 参数；旧的只部署列表方案继续兼容。

恢复分成两步：完整预检并备份部署 → 恢复组合并核对成员 → 对全部有效运行键准备一次定向修改 → 原子写入并重新读取核对。其他 Mod 的键、注释、格式和段落保留。启用列表已一致时也必须执行参数恢复，不能提前提示完成。

组合快照拒绝默认值回退；只要所选 Mod 的受支持持久声明找不到运行值，就应让用户先保存并核对加载器文件。共享 namespace 冲突、重复部署名称、缺失 Mod 或失效声明均停止，避免得到看似成功的部分组合。不能证明一个匹配键是本次游戏的新值，F10 和实际加载状态仍须用户确认。

本次还分离了管理器快捷键与游戏 Mod 快捷键：原先任何 `_modBindings` 匹配都可能触发跳转/部署，此执行路径已移除；仓库 ListView 关闭 SingleSelectionFollowsFocus，刷新保留选择并丢弃过期加载结果。Alt+Tab 的用户桌面回归仍需真实测试。

详细操作与离线/游戏验证方法见 [R3 测试指南](state-slots-test-guide.zh-CN.md)。仓库界面的全面重构留给后续版本，本次没有混入大规模布局修改或正式发布。

## 参考资料与许可边界

- [Peaky Mod Manager](https://github.com/Tian-W001/PeakyModManager_v3) 的 Sync Toggles 采用单向同步：读取 `d3dx_user.ini` 已记录的持久变量，再写到匹配 Mod INI；其说明明确指出不适用于每个 Mod。
- [Global Persist Swapkey](https://github.com/NightLancer/ScriptTools) 说明了“游戏中按 F10 → 读取活动值 → 保存到 Mod INI”的用户流程，也注明链接目录有适用限制。该仓库采用 GPL-3.0；本原型没有复制、翻译或引入它的源码。
- 上述项目是设计和验证线索，不是本项目代码依赖。具体实现仅使用本仓库独立编写的 C# 代码。

## 可操作流程

1. 在“仓库”页选中一个已部署的 Mod，确认目标目录中的同名 Mod 是当前使用的版本。
2. 在游戏中设定外观，按 F10，让 XXMI/3DMigoto 更新 `d3dx_user.ini`。确认游戏退出前文件时间已更新。
3. 在应用里选择该加载器的 `d3dx_user.ini`，点击“保存新槽位”，命名。可以为同一 Mod 保存多个槽位，也可对其他 Mod 分别保存。
4. 先完全退出游戏和加载器，确认当前 Mod 已同名部署，点击“恢复到加载器”。查看目标文件、修改/补入/已一致数量，勾选已退出后执行。
5. 在 d3dx_user.ini 旁创建独立 .bak，原子替换文件并逐项重新读取核对。无需写入 Mod 默认值或重新部署，只需保持该 Mod 的正确部署；重新启动加载器与游戏检查实际效果。

## 严格边界

- 只捕获 `[Constants]` 内的数值型 `$\namespace\variable = number`，用当前 Mod INI 的 `global persist` 声明验证，只恢复匹配的完整运行键。不写 Mod INI，不改其他 Mod 或未声明变量。
- 支持默认命名空间 `Mods\<部署的 Mod 目录>\<相对 INI 路径>` 和首个 section 前显式 `namespace = ...`。命名空间不匹配、声明消失或重复、编码无法安全读取时拒绝写入。
- d3dx_user.ini 的其他内容、其他 Mod 运行键、注释、大小写和编码保持；缺失的有效键补入唯一的 [Constants] 段。重复运行键、无效值或重复/缺失 Constants 段时拒绝恢复。
- 恢复前必须退出游戏和加载器，写入前再次验证 Mod 声明及文件字节未变化。写入后的文件值核对不等于游戏内效果验证。不模拟 F10，不读取或写入游戏内存，不注入 DLL，也不整份使用槽位替换共享配置。
- 当前实现只接受 UTF-8、带 BOM 的 UTF-8 与 UTF-16 INI，保留原换行和 BOM；其他编码拒绝。每个 INI 上限 2 MiB、最多 256 个有效 INI；`d3dx_user.ini` 上限 16 MiB。扫描跳过目录联接和 `DISABLED` 路径。
- 启用 `clear_unknown_settings = 0` 的环境可能保留旧 Mod 的持久值。捕获前须亲自确认当前 Mod 已加载且 F10 已写入新值；仅有键名匹配不等于状态新鲜。多槽位是离线快照，不是自动跟踪。
- 写入前先准备完整修改计划、核对目标文件未变化，再对单个 d3dx_user.ini 原子替换并保留整份备份，随后逐键核对。备份仅用于该次操作回退，存在后续其他修改时不能直接覆盖旧备份。

## 4.0-beta 进展与验证范围

用户已在实际游戏环境确认“恢复 Mod 组合和状态”成功，现将 R3 原型整理为独立 4.0-beta 预发布。它不接入稳定版自动更新，也不代表任意游戏或 Mod 均兼容。组合恢复先重建所选仓库的已识别部署，再一次性定向回写各 Mod 的运行参数；原 Mod INI 仍只读。Alt+Tab 不再经由游戏快捷键触发管理器选择或部署。

## 仍需覆盖的实际验证

单元测试与 WinUI 编译只证明离线解析、备份和界面可构建。还需在用户的实际 XXMI/EFMI + 游戏环境中，用非重要测试 Mod 完成：两组数值状态保存、切换到另一个 Mod、切回并应用槽位、重新启动游戏观察渲染和按键状态；分别覆盖目录联接和普通复制部署。验证前不发布为稳定功能。
