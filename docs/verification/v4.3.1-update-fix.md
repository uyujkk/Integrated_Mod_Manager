# 更新模块问题记录与修复验证

用户反馈：v4.3.0 在更新模块切换检查频率时崩溃，重启后设置已改变。需要 Mod 有更新时的应用内弹窗，以及下载更新并替换旧 Mod 的操作。本轮仅提供测试包，不发布。

基线复现：独立解压 GitHub v4.3.0 正式 ZIP，使用虚构仓库配置；在更新页从“仅手动检查”选择“每天启动时检查”后窗口退出，beta-shell.json 的 ModUpdateCheckInterval 已保存为 Daily。startup.log 记录 Unhandled UI exception / COMException 0x8000FFFF。证据目录为开发根目录 artifacts/update-fix-baseline。

原因与修复：SelectionChanged 中保存后整页刷新，清空并重新创建正在处理选择的 ComboBox；去掉选择回调内的整页刷新，常规刷新复用原有选项，仅同步文字和实际变化的选择。软件更新频率采用同样修复。

新增 Mod 更新流程：手动或按频率检查后发现更新，应用内弹窗提供“查看更新”和“稍后”；更新卡提供“下载并替换”。用户先选择文件／变体，再确认完整替换。先下载和解压暂存，检查原目录指纹，旧版移动到仓库旁 .imm-mod-update-backups，再将完整新版置于原路径。保留旧文件和原跟踪记录，不合并新旧文件；后续修改或链接输入会阻止替换。下载／解压可取消，目录交换阶段不再取消。复制部署需重新部署，目录联接保持原路径。

## 验收结果

- 最终完整回归：969 通过，0 失败、0 跳过（Core 871、Data 24、Updater 27、EndfieldLaunch 47），四组覆盖率门槛通过；WinUI、启动器、更新器构建通过。最后一轮测试版文案更新后，WinUI 增量构建为 0 警告、0 错误。
- 隔离界面点击：修复前选择“每天”即退出；修复后连续选择“每天”“每周”，窗口保持运行，配置分别保存 Daily / Weekly。
- 实际网络与界面：使用独立虚构 Mod 目录和旧时间戳记录，GameBanana 条目 720357 的手动检查弹出更新提醒。最终 4.3.1-test.1 以 Daily 且检查到期启动，同样自动弹出“发现 Mod 更新”。
