# 快捷键面板 test.8 验证

日期：2026-10-22（America/New_York）。基线 fbf47e7 / test.7。未发布，不覆盖用户测试目录、正式版或游戏文件。

## 目标

优化在线 Mod 下载量的采集，尽可能减少页面刷新。

## 原因（实测）

- apiv11 列表接口完全不返回下载量（40 条记录中 0 条含 _nDownloadCount），每张卡片都要补采。
- 原逻辑逐个请求旧版 Core/Item/Data（每页 40 次，间隔 150 ms，约 15 秒以上），每补采 8 个就整页刷新一次，结束再刷新一次（每页约 5–6 次额外整页刷新）。按热度或下载排序时，每次刷新都会重排卡片。
- 卡片内容只在出现时构建一次，补采改动 Mod 数据后卡片上的数字并不会因数据变化自动更新。
- 旧版接口支持批量：40 个 ID 一次请求约 270 ms，结果按请求顺序返回；无效 ID 只返回该项的 error，不影响其他项。

## 修改

- Core GameBananaDownloadCounts：构造最多 40 个 ID 的批量 URL；按位置解析结果，跳过单项错误，返回条数与请求不符时整体拒绝，避免数字错配。
- 加载页面时，先用 12 小时下载量缓存补齐，剩余的一次批量请求（最多等待 2 秒），再一次性显示页面；带下载量写入页面缓存。
- 预取下一页时同时补齐下载量，翻到预取页无需任何请求。
- 批量请求失败或超时：页面照常显示；1.5 秒后后台再批量请求一次，只就地更新可见卡片上的“热度”和“↓”数字，不重建、不重排列表。限流时不请求。
- 列表卡片和网格卡片登记指标更新器（随卡片加载／卸载登记与移除，虚拟化回收不累积）。
