# 快捷键面板 test.7 验证

日期：2026-10-22（America/New_York）。基线 1ff3868 / test.6。未发布，不覆盖用户测试目录、正式版或游戏文件。

## 1. 浮窗只显示已启用的 Mod

- 用 ModCombinationDeploymentPolicy.Capture 识别部署目录中已启用（联接或复制）的仓库 Mod；浮窗下拉框只列这些 Mod。打开浮窗和刷新 Mod 列表时重新读取；无法判断时退回显示全部。
- 当前 Mod 未启用时下拉框显示“当前 Mod 未启用 · 选择已启用的 Mod”。主窗口快捷键页仍列出全部 Mod。
- 角色自动跟随在同一角色有多个 Mod 时优先选择已启用的 Mod。

## 2. Mod 更新页布局

修改前（用户数据截图）：右栏标题显示为“下载量”；“打开组合预设工作区”单独一张卡片；“撤销上次 Mod 操作”按钮悬在开关右侧；安装备份的说明与“空间上限／刷新列表”挤在一行；“仅检查已保存来源 ID…”游离在两张卡片之间；已追踪 Mod 卡片一行最多 5 个按钮且不换行，窄列或双列时会被裁切；列表另有固定高度（460／510）的嵌套滚动。

- “下载量”：本地化表把英文键 Downloads 映射为“下载量”（下载数），改用 Download tasks 键。
- 检查方式提示并入检查方式块；频率下拉框拉伸填满。
- 已追踪 Mod 卡片：标题与状态徽标同行（未检查／已是最新／有更新／检查失败，颜色区分）；路径单行省略、悬停显示全文；操作只保留“下载并替换”（有更新时，主按钮）“打开页面”“更多▾”，打开目录、旧版备份、删除记录进入“更多”菜单。
- 列表随页面滚动，取消嵌套固定高度滚动。
- “打开组合预设工作区”与“撤销上次 Mod 操作”并排放入安装安全卡片；安装备份的数值与刷新按钮单独一行。
- 检查完成后先恢复“手动检查更新”按钮，再弹出结果对话框（原先对话框打开期间按钮仍显示“检查中…”）。

实测：用户数据副本＋5 条测试追踪记录（虚拟目录，真实 GameBanana ID）。检查更新返回 5 个更新，宽屏双列与窄屏单列截图均无裁切。

## 3. 在线 Mod 加载

实测终末地分类 42770：651 个 Mod，每页 50 个共 14 页，单页约 300–400 ms。

- 角色筛选回退（角色没有 GameBanana 子分类 ID 时扫描整个分类）：原为逐页顺序请求，约 3.3–5.5 秒，接近 5 秒超时，且每翻一页都重新扫描整个分类。新增 Core OnlinePageScanner：先读第 1 页取得页数，其余页最多 3 个并发，结果按页序合并；扫描后把每个显示页写入页面缓存。实测同一 14 页扫描：顺序 3331 ms → 3 并发 519 ms，651 个 Mod 无缺失无重复。
- 下一页预取：页面显示后等待 800 ms，若下一页没有缓存且未限流，后台请求下一页写入缓存；切换页面、限流或超时时不预取，失败静默。实测连续翻页：未预取 2153 ms，预取后 229–397 ms。
