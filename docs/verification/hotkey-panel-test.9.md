- 原因确认：更新只把新包内容放进新目录，原目录整体移入备份；预览图（`preview.*` 等）放在 Mod 根目录，无迁移逻辑，新包无图即丢失。

## #16 旧更新器深路径升级失败 —— 已修复（新版更新器）

- 复现：用 test.8 包安装到 185 字符目录（含中文与空格）后用当前更新器升级，备份路径约 325 字符：`PathTooLongException`（LegacyNormalizePath），回滚正常、配置保留。
- 根因：更新器由 csc.exe 编译，无目标框架声明，.NET Framework 在 Main 之前就启用旧版路径处理；即使关闭旧处理，.NET Framework 也不会自动加 `\\?\`，Win32 仍拒绝超长路径（未启用系统长路径时）。在代码中 SetSwitch 无效（已在启动前缓存）。
- 修复：程序集声明 .NET Framework 4.6.2 目标（启用可接受 `\\?\` 的路径处理）；所有文件操作在调用边界对 ≥240 字符的路径加 `\\?\`（网络路径为 `\\?\UNC\`），内部仍用普通路径，枚举结果去前缀；清理旧备份时以普通路径比较，避免误删当前备份。
- 同时修复的潜在缺陷：已安装清单 `.managed-files.txt` 用 `/` 分隔时，与新包路径（`\`）比较全部不相等，子目录文件会被当作“已移除”在复制后删除，导致程序无法启动。正式版 4.3.1 清单用 `\`，不受影响；hotkeys 测试包曾用 `/`（测试版关闭自更新）。读取清单时统一分隔符；测试打包脚本改为 `\`。
- 验证：同一深路径场景用新更新器：退出码 0，新版从 182 字符目录启动，成功日志写入，配置保留；强制启动检查失败触发回滚：回滚日志写入，文件与包逐一比对缺失 0、大小不同 0，配置保留。新增 3 项更新器测试（`/` 清单、长路径前缀规则、超过 MAX_PATH 的备份/复制/回滚），更新器测试 30 项通过。
- 限制：已安装的旧更新器无法事后修复；从旧版升级到本版仍需按 issue 中的临时处理（解压到较短目录）。本版之后的升级使用新更新器。
