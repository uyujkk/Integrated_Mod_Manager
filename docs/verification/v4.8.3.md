# v4.8.3 正式版验证 / Stable release verification

- 基线为 v4.8.2。主程序、启动器、更新器和开发者工具使用产品版本 4.8.3 和文件版本 4.8.3.0（`ApplicationReleasePolicyTests` 检查开发者工具的版本与主程序一致）。
- 本地 `scripts\test-all.ps1` 全部通过，没有警告：Core 1991、DataStore 24、UpdateAgent 33、EndfieldLaunch 47，覆盖率门槛均达到。同一构建上的界面测试 121/121 通过，代码风格检查无问题。
- `package-stable-release.ps1` 用这次的测试结果打包了 `Integrated_Mod_Manager-v4.8.3.zip`；`package-developer-tools.ps1` 打包了 `Integrated_Mod_Manager_Developer_Tools-v4.8.3.zip`，并确认工具的版本与主程序一致。
- **启动和 Mod 工作区（#141–#149）**：
  - 界面测试覆盖以下内容：Mod 工作区从没打开时，启动扫描会建立默认槽位并填充命令面板；扫描结果在第一次打开工作区时显示；仪表板上选择路径、启动器和链接开关会保存，点角色会打开工作区；第一次打开后的行为由已有的工作区测试覆盖。
  - 耗时在同一台电脑上用界面测试的合成数据测得，v4.8.2 和 v4.8.3 的发布构建各运行 7 次取中位数（启动到主界面显示）：仪表板 1034 → 895 毫秒，在线页 952 → 817 毫秒，Mod 工作区 968 → 937 毫秒；第一次切换到 Mod 工作区 208 → 290 毫秒，之后再切换 31 → 41 毫秒（单次在 26–92 毫秒之间波动，与以前相同）。
- **开发者工具（#139）**：界面测试确认设置里的卡片和命令面板里的命令存在（测试副本没有安装工具，所以不点开，以免打开浏览器）。Core 单元测试覆盖工具的查找位置、复制记录和失效链接的检查、日志、缓存（只在主程序关闭时清除可重新生成的文件夹，不跟随链接）、GameBanana 登录数据的清除、翻译对照，以及不含名称、取值和路径的诊断摘要。工具自己的窗口没有自动界面测试。
- **内部结构整理（#141–#149）**：每一步拆分前先写界面测试固定行为（4.8.2 时 79 个，现在 121 个），拆分后在同一构建上运行全部测试。数据格式没有变化。

The v4.8.3 release is based on v4.8.2. The app, launcher, updater and Developer Tools use version 4.8.3 (`4.8.3.0`); a unit test checks that the tools match the app.

- Local `test-all` passed all four suites (Core 1991, DataStore 24, UpdateAgent 33, EndfieldLaunch 47) and the coverage gates with no warnings. All 121 UI tests passed on the same build, and the style check found nothing.
- The stable package script built the app ZIP from these results. The Developer Tools script built `Integrated_Mod_Manager_Developer_Tools-v4.8.3.zip` and confirmed its version.
- Startup and the Mod workspace: UI tests cover the startup scan seeding Default slots and filling the palette while the workspace was never opened, its result showing on the first visit, the Dashboard's path, launcher and link settings being saved, and a Dashboard character opening the workspace. The existing workspace tests cover behaviour after the first visit.
- Timings: release builds of v4.8.2 and v4.8.3 on the same computer with the UI tests' synthetic data, median of 7 (start to the main window shown):

  | Measure | v4.8.2 | v4.8.3 |
  |---|---|---|
  | Startup, Dashboard | 1034 ms | 895 ms |
  | Startup, Online | 952 ms | 817 ms |
  | Startup, Mod workspace | 968 ms | 937 ms |
  | First switch to the Mod workspace | 208 ms | 290 ms |
  | Later switch to the Mod workspace | 31 ms | 41 ms |

  The later switch varies between 26 and 92 ms per run, as before.
- Developer Tools: UI tests check that the Settings card and the palette command exist (the test copy has no tools installed, so they are not invoked, which would open a browser). Core unit tests cover finding the tools, the record and broken-link audit, logs, caches (only regenerable folders, only while the app is closed, never following links), clearing the GameBanana sign-in, translations, and a diagnostic summary without names, values or paths. The tools' own window has no automated UI tests.
- Restructure: before each move, UI tests pinned the behaviour (79 in 4.8.2, 121 now); after it, every suite ran on the same build. No data format changes.

The upgrade and rollback rehearsal from v4.8.2 was not run locally; the tagged release workflow runs it.

Not yet checked outside test windows, synthetic data and offline samples:
- the overlay sending F10 (saving presets, switching state slots) and following characters in a real game;
- the tray icon's own menu and double-click (UI Automation cannot reach the notification area);
- Run launcher with a real launcher;
- Like on the GameBanana page with a real account.
