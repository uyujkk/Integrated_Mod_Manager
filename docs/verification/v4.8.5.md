- 基线为 v4.8.4。主程序、启动器、更新器和开发者工具使用产品版本 4.8.5 和文件版本 4.8.5.0（`ApplicationReleasePolicyTests` 检查开发者工具的版本与主程序一致）。
- 本地 `scripts\test-all.ps1` 全部通过，没有警告：Core 1998、DataStore 24、UpdateAgent 33、EndfieldLaunch 47，覆盖率门槛均达到。代码风格检查无问题。`new-release-notes.ps1 -Version 4.8.5` 生成的发布正文里每个链接都指向 v4.8.5 标签。
- **界面测试**：在这次的构建上（已使用 Windows App SDK 1.7.260224002）一次运行全部 125 个界面测试，全部通过。
- **联接部署（#155，修复 #154）**：
  - `DeploymentSafetyTests` 新增 7 个测试，全部使用真实目录联接：
    - 管理器自己的联接不算重叠，并能认出它指向哪个 Mod；
    - #105 的情况仍然被拦下：加载器设为角色文件夹，或通过链接指到角色文件夹、指到 Mod 自己的文件夹；
    - 普通文件夹、指向其他 Mod 的链接和不存在的路径都不算这个 Mod 的链接；
    - 仓库路径本身是联接时：同角色切换能找到旧链接，删除前的扫描能找到链接，备份和回滚能处理 Mod 自己的链接，组合预设能认出已启用的 Mod 并计划移除；
    - 仓库路径是联接时，指向仓库外的链接仍被备份拒绝。
  - PR #155 的 CI 全部通过：CodeQL、两次完整的测试和 WinUI x64 构建。
- **依赖更新（#153）**：Windows App SDK 1.7.250401001 → 1.7.260224002，Windows SDK 构建工具 10.0.26100.6584 → 10.0.26100.9457。主程序和开发者工具都是自包含发布，运行库打进 ZIP。PR #153 的 CI 全部通过。

The v4.8.5 release is based on v4.8.4. The app, launcher, updater and Developer Tools use version 4.8.5 (`4.8.5.0`); a unit test checks that the tools match the app.

- Local `test-all` passed all four suites (Core 1998, DataStore 24, UpdateAgent 33, EndfieldLaunch 47) and the coverage gates with no warnings. The style check found nothing. `new-release-notes.ps1 -Version 4.8.5` builds the release body, and every link in it points at the v4.8.5 tag.
- UI tests: one full run of all 125 on this build, which already uses Windows App SDK 1.7.260224002; all passed.
- Junction deployment (#155, fixing #154):
  - Seven new `DeploymentSafetyTests`, all with real directory junctions:
    - the manager's own junction is not an overlap, and is recognised as pointing at its Mod;
    - the #105 cases are still blocked: a loader folder set to the character folder, or reaching the character folder or the Mod's own folder through a link;
    - a normal folder, a link to another Mod and a missing path are not the Mod's link;
    - with the repository path itself a junction: the same-character switch finds the old link, the pre-delete scan finds links, the backup and rollback handle the Mod's own link, and combination presets recognise enabled Mods and plan their removal;
    - with the repository path a junction, a link pointing outside the repository is still refused by the backup.
  - All CI checks on PR #155 passed: CodeQL and two full test and WinUI x64 build runs.
- Dependency update (#153): Windows App SDK 1.7.250401001 → 1.7.260224002, Windows SDK build tools 10.0.26100.6584 → 10.0.26100.9457. The app and the Developer Tools are self-contained, so the runtime ships in the ZIP. All CI checks on PR #153 passed.

The upgrade and rollback rehearsal from v4.8.4 was not run locally; the tagged release workflow runs it.

Not yet checked:
- turning off a junction-deployed Mod in a real game with the EFMI loader;
- screenshots of the new "Link from elsewhere" confirmation, and a native review of its Russian text;
- the checks listed for 4.8.4 and 4.8.3.
