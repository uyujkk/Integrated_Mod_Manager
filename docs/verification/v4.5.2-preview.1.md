## Synthetic UI and F10 receiver / 合成 UI 与 F10 接收器

使用专用 `ImmShortcutBenchmark=true` 构建，包含 `tests/Performance/ShortcutUiBenchmark.cs`。正常发行构建不包含这个入口。接收器为独立的合成 WinForms 程序，未连接真实游戏。

- 模拟目录联接部署：A 被 B 替换后浮窗选中 B、只显示 B 的按键；停用 B 后清空旧按键；新增 C 后手动刷新可见 C。
- 实际使用快捷键发送服务向合成接收器发送 F10：磁盘原值为 0，接收器内存值为 7，保存的组合参数为 7。
- 接收器忽略 F10 时 5 秒超时，组合预设数量不增加。
- 模拟热应用持有只读文件：保存等待其完成，属性恢复后成功发送并保存。
- 缺少参数时不保存，错误提示经过中英文资源映射。
- 浮窗反复关闭、重建时清理旧窗口控件缓存，修复基准中发现的跨窗口控件归属问题；连续 100 次状态更新不替换已有按键按钮。

## Boundaries / 验证边界

- 原生 F10 的成功证据限于合成接收器；真实游戏、XXMI/EFMI、独占全屏和管理员游戏仍待实测。单 Mod 命名对话框沿用 v4.5.1 的实现；本轮验证了两按钮共用的同步步骤，未重做该对话框的独立 UI Automation 验收。
- 变体文件导入只使用合成数据和单元测试，没有真实导出文件验证。菜单和结果提示保留“待验证”。
- 链接部署、加载器状态恢复和组合预设移除实验标记的依据为既有自动测试及 v4.5.0 验证记录里的用户真实 EFMI 仓库实测；不扩展为所有游戏兼容性证明。F10 热应用及在线自动翻译的实验标记不变。
- 本轮提供本地预览，不修改 GitHub 上既有 Release 文本，也不合并目录整理到主线。远端精确提交 CI、PR 合并和已发布说明同步仍属于后续发布工作。

English: all four suites and coverage gates are retained. Synthetic WinUI checks cover link replacement, disabled-action clearing, new-Mod refresh, native F10 capture of updated receiver memory, timeout rejection, queuing behind a read-only hot apply, and localized missing values. The UI benchmark shows cached scans and unchanged control reuse are inexpensive; initial layout and overlay creation still cost time. These checks do not establish real-game delivery, real exported-variant compatibility or remote release completion.
