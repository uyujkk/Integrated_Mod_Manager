# Mod 快捷键面板（独立测试版）

**test.6：浮窗集成游戏内可用的功能**

浮窗只放“在游戏运行中也安全”的操作，避免功能堆叠：

| 浮窗中可用 | 说明 |
| --- | --- |
| 切换 Mod | 顶部下拉框，与主窗口同步；手动切换会暂停角色自动跟随。 |
| 发送：开／关 | 可在浮窗开启或暂停发送；目标游戏窗口仍需在主窗口选择。 |
| 保存预设 | 把当前启用的 Mod 组合和 d3dx_user.ini 中的参数保存为组合预设，名称为“游戏内 月-日 时:分”。只读取，不改动游戏。刚调整的 Mod 状态需先在游戏中按 F10 写入再保存。 |
| 隐藏、不透明度 | 同前。 |

保留在主窗口的功能：恢复组合预设和状态槽位（需先退出游戏和加载器，再写入部署目录与 d3dx_user.ini）、仓库与路径设置、在线浏览与下载、导入、冲突检测、终末地启动设置。这些操作要么需要游戏关闭，要么需要键盘输入或大量确认，放进不抢焦点的浮窗会造成误操作或无法确认。

另外修复：仓库设置为复制部署、但部署目录中已存在指向仓库源目录的联接时，保存组合预设会报“Select a real Mod folder, not a directory link.”；现在指向自身源目录的联接视为同一文件，跳过副本校验，指向其他位置的联接仍会被拒绝。

终末地启动设置对话框：内容区改为固定高度并显示滚动条，下方的检查、许可证与风险确认不再被裁掉；风险确认移到启动方式开关下方（它决定能否保存）；检测结果显示在底部单独区域，可关闭，不再把设置往下推；开关说明改为可换行的文字，长标签自动换行。

**test.5：** 快捷键页和浮窗完整支持英文界面；在设置中切换语言后，面板与浮窗会立即按新语言重建，保留所选 Mod 和目标窗口（按键发送开关需重新开启）。

**test.4：**
- 状态文字改为固定高度（超出部分显示省略号，鼠标悬停可看全文），发送或角色识别更新状态时，快捷键列表不再跳动。
- 浮窗背景可调不透明度（10%–100%），只改变背景，文字和按钮始终清晰不透明；主窗口和浮窗里各有一个滑块，二者同步并保存。
- 浮窗字体颜色可自定义：主窗口“浮窗字体颜色”提供常用色和取色器，保存在程序配置中。
- 浮窗标题栏改为与面板一致的深色；默认窗口更高（约 860 DIP，不超过屏幕工作区）。
- 按 3DMigoto 规则补全了按键识别：`/`、`[`、`]`、`=`、`'`、`\`、反引号等标点键；多个普通键组合（如 `VK_RETURN VK_UP` 表示按住 Enter 再按上）；`no_` 可以排除任意键（如 `NO_VK_RETURN NO_VK_BACK VK_UP`）。
- 无法发送的绑定会直接显示原因和原始写法；可开启“隐藏无法发送的绑定”。

### 为什么有些快捷键选不了

| 原因 | 例子 | 解决办法 |
| --- | --- | --- |
| 鼠标按键 | `VK_LBUTTON`、`VK_RBUTTON`、`VK_XBUTTON1` | 这类通常是 Mod 内置菜单的点击、拖动、滑块操作，需要鼠标指在游戏画面的具体位置，面板无法代替。打开 Mod 菜单后直接用鼠标操作。 |
| 手柄按键 | `XB_LEFT_THUMB`、`XB_DPAD_UP` | 键盘模拟无法产生手柄输入（需要虚拟手柄驱动）。同一节通常还有键盘绑定，面板会列出可发送的那一条；也可以直接用手柄。 |
| 系统组合键 | `alt F4`、`WIN` 键 | 为防止误关游戏或触发系统功能而禁止。如确需使用，请在 Mod INI 中改成其他按键。 |
| 无法识别的键名 / 条件矛盾 | 拼写错误、同一键既要求按下又要求不按 | 检查并修正 Mod INI 中的 `key =` 写法。 |

**test.3 重点：终末地需要以管理员身份运行管理器。** `Endfield.exe` 的清单声明 `requireAdministrator`，游戏始终以管理员权限运行。Windows 的 UIPI 会把普通权限程序发往管理员窗口的模拟按键静默丢弃，且发送函数仍返回成功，因此旧版显示“已发送”但游戏没有反应。物理键盘不受影响；`Win + Ctrl + O` 的经典屏幕键盘带有 `uiAccess` 特权，因此也能输入。test.3 在发送前识别这种情况并拒绝发送，不再显示误导性的“已发送”。请在“快捷键”模块点击 **以管理员身份重启管理器**（会弹出一次 UAC），重启后状态会显示“管理器以管理员权限运行”。以管理员权限运行时，Windows 不允许从普通权限的资源管理器拖放文件到管理器，导入 Mod 请使用选择文件按钮，或改回普通权限运行。

test.2 修复浮窗滚动回顶部，默认增加扫描码输入，保留虚拟键模式供对照。单次按压默认 200 毫秒，可调至 100–2000 毫秒；小键盘数字在扫描码模式下需要开启 Num Lock，可用模块中的按钮切换。

若游戏无响应：先确认目标是游戏本体、开启发送，再分别测试扫描码／虚拟键模式；可将单次按压调到 500 毫秒排查短按漏读。若明确提示权限不足，请以与游戏相同的权限打开管理器。权限无法读取会标为未知，不会推断已绕过限制。

每次点击会在当前程序 `WinUI3/diagnostics/shortcut-input.jsonl` 保存本地诊断：输入模式、虚拟键／扫描码、Windows 接收数量、按下状态、前台窗口和权限检查。日志不自动上传。“Windows 已接收、按下状态已观察到”仍不代表游戏执行了 Mod 动作。

Windows 经典屏幕键盘与普通程序的权限和输入方式并不相同；不能因经典屏幕键盘可用就认定普通程序必然可用。参考：[SendInput 权限限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[扫描码输入](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput)、[辅助功能 UIAccess](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview)。

在左侧“快捷键”模块选择当前仓库内的 Mod，再选择游戏窗口。读取 INI 后会显示按键、动作说明、来源节和条件。开启“允许向所选窗口发送按键”，点击按钮即可输入；Num5 会发送数字小键盘 5，与数字行 5 不同。无需实体小键盘。

“独立置顶面板”提供类似屏幕键盘的点击操作。默认全局快捷键 **Ctrl + Alt + K** 显示或隐藏浮窗，可在模块内更换或禁用，设置保存在当前程序配置中。注册冲突会提示并保留原设置。浮窗可拖动、调整大小、暂停发送；隐藏后通过全局快捷键恢复。

浮窗面向窗口化与无边框全屏。独占全屏、不同权限等级、游戏对模拟输入的处理需要实际验证；Windows 接收输入不等于游戏一定执行。发送时校验目标进程和窗口、检查用户是否按住其他键，并在完成、失焦或关闭时释放本次按下的键。仅用户点击会发送按键，角色识别不会自动执行 Mod 快捷键。

## 跟随当前出场角色

1. 选择目标游戏窗口，点击“框选识别区域”。程序读取前台游戏画面，拖框选出**只随当前出场角色变化**的头像或名称，保存区域。不要选择始终展示整个队伍的固定列表。
2. 在游戏中切到某角色，在管理器中选择该角色对应的 Mod，点击“保存当前角色参考图”。对需要跟随的角色重复此步骤。
3. 开启“自动切换角色快捷键”，回到游戏。每约 700 毫秒比对一次本地参考图，连续 3 次达到阈值且领先其他角色后切换面板。未知、低匹配、相似度难区分或目标不在前台时不切换。
4. 手动选择 Mod 会暂停跟随；同角色多个 Mod 使用保存参考图时选定的 Mod。浮窗遮住识别区时暂停识别并提示移动。重设区域会清除旧区域参考图。

参考只保存在程序目录 `character-references`，按仓库区分；仅保存裁剪后 24×24 像素特征及对应角色，不保存完整游戏截图或上传画面。自动跟随每次启动默认关闭。游戏分辨率、HUD 比例、头像或界面变化后可能需要重新校准。该机制需要用户录入参考图，不能无需配置就识别所有游戏角色。

## 支持范围

- 读取启用的 INI `[Key…]` 绑定，跳过 `DISABLED` 文件和子目录；只读扫描，不修改 Mod INI。
- 支持字母、数字、F1–F24、数字小键盘、常见导航键和 Ctrl/Alt/Shift 组合。保留 `no_*` 原始约束；`VK_MENU` 是 Alt，`VK_APPS` 才是独立菜单键。
- 长按类绑定按设定时长（100–2000 毫秒）发送，不持续重复。
- 未识别、鼠标、控制器、矛盾绑定和受限系统组合会显示但禁用。INI 条件仅展示，不会假定其当前在游戏中成立。
- 同键可能触发多个 Mod；面板不能绕过加载器的按键冲突或判断哪一个 Mod 当前实际绘制。
