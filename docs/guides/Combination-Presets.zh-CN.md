# 4.0 仓库与组合预设

在“仓库”顶部选择文件列表、封面视图或组合预设。新配置默认使用文件列表；视图选择会保存，切换视图不会部署 Mod。

## 文件与封面

左侧选择角色，中间搜索和选择 Mod。宽窗口右侧显示预览、快捷键和状态槽位；窄窗口使用顶部“详情”按钮。部署操作位于详情底部；进入详情或单击选择不会自动部署。双击 Mod 仍沿用原有部署操作。

## 保存组合与状态

1. 在当前仓库部署需要的 Mod。
2. 在游戏中调整状态，按 F10 并等待加载器完成持久参数保存。
3. 进入“组合预设”，勾选“同时保存 d3dx_user.ini 参数”，选择当前加载器实际使用的文件。
4. 点击“新建方案”命名保存；“更新方案”会更新当前选中的方案。

只想保存启用组合时，取消参数选项。左侧列出当前仓库的预设，中间展示成员和参数数量。

## 恢复

先退出游戏和加载器。选择预设，点击“恢复组合”，检查变更预览后确认。程序先恢复可识别的 Mod 部署，再写回匹配的数值型持久参数，并保留其他 Mod 的参数。不会把状态写进 Mod 原始 INI，也不会发送游戏快捷键。

未知目标目录、namespace 冲突、重复部署名或并发修改会受到现有保护检查。备份可从更新页查看。该流程不保证任意 Mod、加载器版本或游戏环境兼容，也不构成账号安全保证。

## 升级

### 4.1：组合包迁移

“组合预设”中新增“导出组合包”和“安装组合包”。导出所选预设**已保存的参数**与全部对应 Mod 文件；要保存最新状态，请先更新组合。导入会列出新安装、文件相同可复用及冲突项；不覆盖内容不同的已有 Mod，不自动改目录名。

安装确认后保存为新预设，默认再进入恢复确认；也可取消勾选，仅安装保存。恢复前请退出游戏和加载器。恢复仍为先部署组合，再定向回写本地 `d3dx_user.ini`，不改原 Mod INI、不影响其他键。压缩包不加密，分享前检查私人文件和作者许可。支持本应用生成的组合 ZIP，不把普通 Mod 压缩包识别成组合预设。

详细边界及测试方法见[组合包说明](../development/Combination-Bundles.md)。4.1.0 起提供这些按钮；旧版 4.0.0 不包含组合包迁移。

4.1.0 使用 `IntegratedModManager.exe`，不包含模拟仓库。旧 `config.ini`、`beta-shell.json`、组合方案和状态槽位格式继续使用，参见[升级指南](./Upgrade-v4.1.zh-CN.md)。不要从模拟仓库复制测试配置到实际游戏环境。

## 参数与备份边界

- 只支持可识别的数值型 `global persist`；捕获时须在真实参数文件中存在，不会用 Mod INI 默认值代替缺失数据。
- 只管理当前仓库可识别部署。普通复制按唯一同名目录识别，无法区分手工创建的同名副本，请检查移除清单；联接会核对实际目标。
- 单 Mod 状态槽位位于 Mod 详情内，用于同一 Mod 的多个状态，不把参数强行移植给其他 Mod。
- 组合存于 `WinUI3/beta-shell.json` 的 `ConfigurationProfiles`，状态槽位存于 `ModPersistentSlots`。重命名目录、修改命名空间或更换 Mod 版本后，可能需要重新捕获。
- 参数回写前生成文件旁的 `d3dx_user.ini.imm-persist-*.bak`；安装备份在“更新”里。部署撤销不会撤销参数，不要把旧的整文件备份直接覆盖到有更新修改的文件上。
- 管理器不会注入、读写游戏内存、自动按 F10 或强制结束游戏。请自行确认退出状态；文件验证不等于游戏画面验证。
