# 集成化 Mod 管理器 v3.8.5 更新报告

> **目录联接部署与稳定性更新 / Directory Junction Deployment and Stability Update**

- 显示版本：`v3.8.5`
- 文件版本：`3.8.5.0`
- 工具作者：`uyujkk`

## 中文

v3.8.5 在 v3.8.0 的现有功能与默认复制模式上，加入可选目录联接部署，并集中修复 RAR 导入、Mod 选择稳定性和下载进度显示。

### 目录联接部署

- 每个仓库可独立选择复制模式或 Windows 目录联接模式。
- 目录联接让加载器与仓库访问同一个 Mod 目录，Mod 文件夹内部的配置写入会直接留在仓库中。
- 同一角色改为链接另一个 Mod 时，程序只断开受管的旧目录联接，然后创建新联接。
- 移除联接只删除重解析点，不递归删除仓库源目录；普通复制目录和其他角色不会被自动移除。
- 该功能不覆盖 EFMI 根目录的 `d3dx_user.ini`，也不能保存只存在于游戏进程内存的状态。

### 修复

- 修复新版 7-Zip 的 RAR 清单包含空链接字段时被错误拒绝的问题；真实符号链接或硬链接仍会被阻止。
- 选择 Mod 时的目录、图片、快捷键和来源链接读取增加完整异常边界，快速选择不会再让过期图片覆盖当前结果。
- 下载任务卡改为原位更新；阶段和百分比只能向前推进，未知大小使用不确定进度动画。

### 跨 Mod 内部状态研究结论

v3.8.1 的整文件热覆盖、按变量恢复与双 F10 桥接，以及 v3.8.2 的 EFMI 常驻控制器均为未发布实验。它们依赖第三方 Mod 的变量声明、命名空间、加载顺序或重载行为，不能可靠适用于任意 Mod，现阶段标记为暂时无法实现，不包含在 v3.8.5 发布包中。详见 [跨 Mod 内部状态保存：试验路线与当前结论](./docs/跨Mod状态保存试验结论.md)。

### 验证

- 三组自动化测试合计 99 项。
- 执行覆盖率门槛检查、WinUI x64 Release 构建和精简发布包结构验证。

## English

v3.8.5 adds optional directory-junction deployment on top of the existing v3.8.0 feature set and default copy mode, while fixing RAR import, mod-selection stability, and download progress.

### Directory-junction deployment

- Each repository can independently use copy deployment or Windows directory junctions.
- A junction lets the loader and library access one physical mod directory, preserving writes made inside the mod folder.
- Linking another mod for the same character disconnects only the managed previous junction before creating the new one.
- Removing a link deletes only the reparse point, never the library target. Copied folders and other characters are not automatically removed.
- This does not cover EFMI's root-level `d3dx_user.ini` or state that exists only in game-process memory.

### Fixes

- Fixed false rejection when modern 7-Zip RAR listings contain empty link fields; real symbolic links and hard links remain blocked.
- Added complete exception boundaries for directory, image, hotkey, and source-link reads during mod selection; stale image loads cannot replace the current selection.
- Download cards update in place, phases and percentages are monotonic, and unknown sizes use indeterminate progress.

### Cross-mod internal-state conclusion

The v3.8.1 whole-file replacement, variable restore, and two-F10 bridge prototypes, plus the v3.8.2 EFMI resident controller, were never released. They depend on third-party variable declarations, namespaces, load order, or reload semantics and are not reliable for arbitrary mods. Universal restoration is currently marked temporarily infeasible and is not included in v3.8.5. See [Cross-Mod Internal State: Experiment Routes and Current Conclusions](./docs/跨Mod状态保存试验结论.md).

### Verification

- 99 automated tests across three suites.
- Coverage gates, WinUI x64 Release build, and minimal release-package structure verification.
